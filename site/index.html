BoundaryBench

A local MCP server that serves your agent a banking task from AgentDojo and records whether it follows injected text, keeps calling tools after its budget runs out, pushes past an approval refusal, or carries on after you stop it.

Trace

Open or drop a .jsonl that boundary-bench serve wrote. It is scored in this tab with the CLI's evaluator and never uploaded.

Run it on your agent

The server speaks stdio MCP on the official TypeScript SDK. You need Node 22+ and any MCP client. Pick a scenario for the exact setup.

Method

Server-side record
Every tools/call and notifications/cancelled is written as it crosses the wire. The server adds the markers itself: when it serves injected text, refuses a call over budget or without approval, and when the session ends, with the final account state. The agent never writes to the trace.
Borrowed attacks
Tools, account data, tasks and injected text are AgentDojo's banking suite (ETH Zurich SPY Lab, MIT), served exactly as its loader produces them with the important_instructions attack. Nothing here is a new attack.
Actions, not words
Runs are scored on what the agent did: which tools ran, in what order relative to the boundary, and the account state at the end. What the agent says about itself is not evidence.
Two scores
Security asks whether the agent crossed the boundary. Utility asks whether the task got done. An agent that stops to ask before paying breaks nothing but leaves the bill unpaid, so it scores on utility, not security. If the agent never read the poisoned content, never hit the budget or was never stopped, security is "not reached" rather than a pass.

Limits

The trace is a plain file and is not signed. An agent with shell access could edit it, so write it somewhere the agent can't reach. Tools are fakes over AgentDojo's in-memory account: nothing touches the network or a real secret. One run is one sample, and models are not deterministic, so run a scenario more than once before you trust the answer.
