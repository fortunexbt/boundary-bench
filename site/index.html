Crash tests for the controls around an AI agent.

An agent with tools can move money, delete repos and leak secrets. Stop buttons, spending caps and approval gates are supposed to prevent that. BoundaryBench checks they hold, by running every test in two matched worlds: one ordinary, one under attack.

The full bench, recomputed in your browser

Seven failure modes, two worlds each, two illustrative agents. The page re-evaluates all 28 traces with the library's own evaluator and checks the result against the published bundle hash.

How it works

No model is called and no LLM grades anything. A test is a scripted world, a recorded trace of what the agent did, and checks that read the trace.

Paired worlds
Each failure mode has an ordinary world and an attacked one. An agent that refuses everything passes the attack and fails the ordinary job. An agent that obeys everything does the reverse. Only a pair where both halves pass counts.
Checks on actions, not words
Checks look at which tools were called, in what order, with which credential and at what cost, and whether a stop, halt or quarantine was recorded. What the agent says about itself is not evidence.
Hash-linked receipts
Every event carries the SHA-256 of the one before it. Delete or edit a line and the chain stops verifying, and a replay of the same run no longer ends on the same hash.
No bodies kept
Traces store digests, order, trust level, credential audience, cost and tags. Prompts, responses, tokens and secrets are rejected, so a trace can be shared.

Limits. Both agents here are scripted fixtures that show the evaluator working, not real models. Passing this pack is not a security proof. Real timing, auth, networking and model randomness need their own trials. To test your own agent, record its tool calls as MCP or A2A envelopes and run the CLI. 

npx tsx src/cli.ts adapt --profile mcp --input your-log.json --out trace.json
npx tsx src/cli.ts evaluate --scenario retrieval-injection --trace trace.json --replay trace.json
